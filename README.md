# living-together-app 仕様書

## 1. アプリ概要

同居する2人が、買い物・レシート・家計簿・共同生活費の精算を一元管理するアプリ。

日々の買い物を記録するだけでなく、レシートをAIで解析し、購入履歴や家計簿へ自動的に反映する。

また、2人がそれぞれ支払った共同生活費を集計し、最終的な負担額が均等になるように精算額を自動計算する。

---

## 2. アプリの目的

以下を一つのアプリで管理する。

* 買い物リスト
* 購入履歴
* レシート
* 家計簿
* 支出カテゴリ
* 支払った人
* 共同生活費
* 2人の支払額の差額
* 共同生活費の精算

最終的には、

> 「何を買ったか」
>
> 「いつ買ったか」
>
> 「いくらだったか」
>
> 「誰が払ったか」
>
> 「何のカテゴリだったか」
>
> 「今月どちらがいくら多く払っているか」
>
> 「最終的に誰が誰にいくら払えばよいか」

を一目で確認できる状態を目指す。

---

同居している2人。

例：

* カップル

MVPでは2人での共同生活を前提とする。

買ってきてほしい商品を登録・管理する。

2人がそれぞれ支払った共同生活費を集計し、均等負担になるよう精算額を自動計算する。

# 6. 買い物リストの仕様

買い物リストの商品は以下の情報を持つ。

* 商品名
* 数量
* 購入済み状態
* 登録したユーザー
* 作成日時
* 更新日時

例：

```text
牛乳  1個  未購入
卵    1パック  未購入
洗剤  1個  購入済み
```

レシート解析後、商品名を買い物リストと照合する。

一致した商品は自動的に購入済みにする。

# 7. レシート管理

レシートは以下の情報を持つ。

* 店舗名
* 購入日時
* 合計金額
* レシート画像
* 登録したユーザー
* AI解析状態
* 作成日時
* 更新日時

レシート1枚に複数の商品が存在するため、レシート本体と商品情報は分離して管理する。

```text
Receipt
 ├── ReceiptItem
 ├── ReceiptItem
 └── ReceiptItem
```

# 8. レシートAI解析

レシート画像をAIに渡し、以下の情報を自動解析する。

* 店舗名
* 購入日時
* 商品名
* 商品価格
* 数量
* 商品カテゴリ
* 合計金額

処理フロー：

```text
レシート画像
      ↓
AI解析
      ↓
商品・価格・カテゴリ抽出
      ↓
ユーザー確認・修正
      ↓
保存
```

AIの解析結果は、そのまま確定保存しない。

ユーザーが確認・修正してから正式なデータとして保存する。

# 12. 買い物リストとの連携

レシート解析で取得した商品と買い物リストの商品を照合する。

例：

```text
買い物リスト

牛乳
卵
洗剤
```

レシート：

```text
牛乳
卵
洗剤
```

一致した場合：

```text
牛乳 → 購入済み
卵   → 購入済み
洗剤 → 購入済み
```

と自動更新する。

商品名が完全一致しない場合も考慮し、将来的にはAIや類似文字列による照合を検討する。

# 13. 商品照合

商品照合では以下のような表記揺れを考慮する。

```text

レシート　　：牛乳 1L
```

```text
買い物リスト：食器用洗剤
レシート　　：食器洗剤
```

MVPでは完全一致または単純な正規化による照合から開始し、必要に応じてAIによる照合へ拡張する。

# 16. カテゴリの管理方法

カテゴリは親子関係を持つ。

```text
食費
 ├── 肉・魚
 ├── 野菜・果物
 ├── 乳製品
 └── 卵

日用品
 ├── 洗剤・掃除用品
 └── キッチン用品

住居・光熱費
 ├── 家賃
 ├── 電気代
 ├── 水道代
 └── ガス代
```

`categories` テーブルでは `parent_id` を利用して親子関係を表現する。

MVPではカテゴリの自由なCRUD機能は提供せず、アプリで定義したカテゴリを使用する。

# 18. 共同生活費

家計簿の支出のうち、2人の共同生活に必要な支出だけを精算対象とする。

## 精算対象

* 食費
* 日用品
* 家賃
* 電気代
* 水道代
* ガス代
* その他、共同生活のための支出

## 精算対象外

個人的な支出。

例えば、

```text
自分だけが使用する趣味の商品
自分だけの衣類
自分だけの娯楽
```

などは家計簿には登録できるが、共同生活費の精算には含めない。

---

# 19. 共同生活費の精算方法

MVPでは、共同生活費を2人で **50:50** で負担する。

例えば、

```text
Aさん：80,000円支払い
Bさん：40,000円支払い

共同生活費合計：120,000円
```

1人あたりの負担額：

```text
120,000 ÷ 2 = 60,000円
```

実際の支払額との差額：

```text
Aさん
80,000 - 60,000 = +20,000円

Bさん
40,000 - 60,000 = -20,000円
```

したがって、

```text
Bさん → Aさん

20,000円
```

と表示する。

---

# 20. 精算の表示

精算画面では、例えば以下のように表示する。

```text
2026年9月の共同生活費

共同生活費合計
120,000円

Aさんの支払額
80,000円

Bさんの支払額
40,000円

1人あたりの負担額
60,000円

────────────────

精算額

Bさん → Aさん

20,000円
```

精算済みになった場合：

```text
Bさん → Aさん
20,000円

✓ 精算済み
```

と表示する。

---

# 21. 精算対象の判定

各 `Transaction` に共同生活費かどうかを判定できる情報を持たせる。

```text
is_shared
```

例：

```text
家賃       80,000円   is_shared = true
食料品      5,000円   is_shared = true
趣味の服    8,000円   is_shared = false
```

`is_shared = true` の支出だけを精算計算に使用する。

# 24. レシートと家計簿の連携

レシートを確定すると、そのレシートの購入内容を家計簿へ反映する。

```text
レシート
    ↓
ReceiptItem
    ↓
カテゴリ判定
    ↓
Transaction
```

例えば、

```text
牛乳 238円 → 食費 / 乳製品
卵   298円 → 食費 / 卵
洗剤 398円 → 日用品 / 洗剤・掃除用品
```

の場合、

```text
食費       536円
日用品     398円
```

として集計できる。

# 38. MVPでの重要な設計原則

このアプリでは、以下の3つを明確に分離する。

### ① 支払った人

実際にお金を出した人。

```text
Aさんが10,000円払った
```

### ② 共同生活費かどうか

その支出が2人の生活のためのものか。

```text
食料品 → 共同
家賃 → 共同
自分だけの趣味 → 個人
```

### ③ 最終的な精算

共同生活費について、2人の負担額が均等になるよう差額を計算する。

```text
共同生活費
    ↓
各ユーザーの支払額
    ↓
合計 ÷ 2
    ↓
各ユーザーの本来の負担額
    ↓
実際の支払額との差額
    ↓
精算額
```

この3つを分けることで、家計簿と精算を柔軟に管理できる。
